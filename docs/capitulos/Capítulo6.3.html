Muestras complejas con survey

¿Por qué hace falta un paquete especial?

Una encuesta real casi nunca es una MAS. Suele combinar tres elementos, y los tres cambian el análisis:

Elemento del diseño Qué hace Qué se pierde si se ignora
Pesos (weights) Cada persona representa a un número distinto de adultos Sesgo en las estimaciones
Conglomerados (PSU) Personas agrupadas en comunidades EE demasiado pequeño
Estratos Muestreo separado por grupo EE demasiado grande (se pierde precisión)

El paquete survey (Thomas Lumley) incorpora los tres. Se define una vez el diseño y luego se usan funciones análogas a las de siempre: svymean(), svytotal(), svyby(), svyglm().

La encuesta de ERC

encuesta_erc.csv (simulada) tiene 1 500 adultos: 30 comunidades urbanas y 30 rurales (muestreo bietápico estratificado), con 25 adultos sorteados en cada comunidad. Las zonas rurales se sobremuestrearon: hay el mismo número de comunidades en ambas áreas aunque la zona urbana tiene más habitantes.

library(survey)

  • area: estrato (urbano o rural).
  • peso: inversa de la probabilidad de selección = \(1/(p_1 \times p_2)\), con \(p_1\) la probabilidad de elegir la comunidad y \(p_2\) la de elegir al adulto dentro de ella.
  • tam, N_conglom: datos auxiliares usados para calcular el peso.
enc |>

  summarise(adultos = n(), comunidades = n_distinct(cluster),
            peso_medio = mean(peso), adultos_representados = sum(peso))

Un adulto rural representa a unos 29 adultos de la región y uno urbano a unos 71. La suma de pesos (≈ 75 000) estima el tamaño de la población.

Paso 1: declarar el diseño

dis <- svydesign(
  ids     = ~cluster,    # unidades primarias de muestreo (comunidades)
  strata  = ~area,       # estratos
  weights = ~peso,       # pesos de muestreo
  data    = enc,
  nest    = TRUE         # los id de comunidad se repiten entre estratos: anidar
)
dis
Stratified 1 - level Cluster Sampling design (with replacement)
With (60) clusters.
svydesign(ids = ~cluster, strata = ~area, weights = ~peso, data = enc, 
    nest = TRUE)
Tip💡 Tip práctico: qué poner en cada argumento
  • ids: la primera etapa del muestreo (comunidad, hospital, unidad de diálisis). Si es MAS sin agrupar, ids = ~1.
  • strata: la variable usada para estratificar. Si no hubo, se omite.
  • weights: la columna de pesos. Los publica la encuesta (ENSANUT, NHANES) con la base.
  • nest = TRUE cuando los códigos de conglomerado se repiten dentro de distintos estratos.
  • Con encuestas públicas, lee el manual para saber cuáles son las variables de diseño: usar la equivocada es un error silencioso.

Comparar con el análisis “ingenuo”

p_ingenua <- mean(enc$erc)
ee_ingenuo <- sqrt(p_ingenua * (1 - p_ingenua) / nrow(enc))

tibble(
  metodo = c("Ingenuo (sin pesos, MAS)", "Con el diseño (survey)"),
  prevalencia = c(p_ingenua, coef(est)),
  EE = c(ee_ingenuo, SE(est)),
  IC_inf = prevalencia - 1.96 * EE,
  IC_sup = prevalencia + 1.96 * EE
) |> mutate(across(where(is.numeric), \(x) round(100 * x, 2)))
# A tibble: 2 × 5
  metodo                   prevalencia    EE IC_inf IC_sup

1 Ingenuo (sin pesos, MAS)        9.4   0.75   7.92   10.9

Dos efectos distintos pueden aparecer:

  • El punto puede cambiar (sesgo por no ponderar): el análisis ingenuo da demasiado peso a la zona rural (la mitad de la muestra, pero solo el 29 % de la población). Aquí el cambio es pequeño porque la prevalencia rural y urbana no difieren tanto; con estratos muy distintos, ignorar los pesos puede equivocar bastante.
  • El error estándar cambia casi siempre: con el diseño es mayor, porque las personas de una misma comunidad no aportan información independiente (deff = 1.88). El IC ingenuo es demasiado optimista.
Importante🎯 Regla de oro

Si tu base viene de una encuesta con diseño complejo, todo análisis (descriptivo, regresión, tablas) debe pasar por el diseño. Un mean() o glm() sin pesos entrega una estimación para la muestra, no para la población.

Advertencia⚠️ Subpoblaciones: usa subset() sobre el diseño, no filter() sobre los datos

Si quieres solo a los mayores de 60 años, no elimines filas de la base antes de crear el diseño: se pierde información de conglomerados y estratos y el EE sale mal. Filtra el objeto de diseño:

dis_60 <- subset(dis, edad >= 60)
svymean(~erc, dis_60)

Regresión con el diseño

svyglm() ajusta modelos lineales generalizados teniendo en cuenta pesos y conglomerados. Para un desenlace binario se usa la familia quasibinomial (evita avisos por pesos no enteros; los coeficientes son los mismos que con binomial).

m_svy <- svyglm(erc ~ diabetes + hta + I(edad / 10) + area, design = dis, family = quasibinomial)

tab <- cbind(coef(m_svy), confint(m_svy))
round(exp(tab[-1, ]), 2) |> `colnames<-`(c("OR", "IC_inf", "IC_sup"))
             OR IC_inf IC_sup
diabetes   4.24   2.47   7.28
hta        2.05   1.18   3.57
I(edad/10) 1.52   1.31   1.77
areaUrbano 0.99   0.63   1.57

Comparado con el modelo sin diseño:

m_ing <- glm(erc ~ diabetes + hta + I(edad / 10) + area, data = enc, family = binomial)
round(exp(cbind(OR = coef(m_ing), confint.default(m_ing)))[-1, ], 2)
             OR 2.5 % 97.5 %
diabetes   3.56  2.16   5.88
hta        1.95  1.26   3.00
I(edad/10) 1.55  1.36   1.77
areaUrbano 1.00  0.69   1.44

Los OR son parecidos; los IC del modelo con diseño suelen ser más anchos para las variables que varían entre comunidades.

Nota¿Pesos en una regresión? Una discusión abierta

Cuando se estima un parámetro poblacional descriptivo (prevalencia, totales), los pesos son indispensables. Para estimar asociaciones con un modelo bien especificado que incluye las variables de selección (aquí area), un modelo sin pesos es válido y más eficiente, pero con conglomerados hay que corregir el EE de todos modos (errores robustos por conglomerado, o modelos mixtos). Los pesos protegen frente a una mala especificación. En la práctica con encuestas oficiales: se analiza con el diseño.

Alternativas cuando no hay survey

Si trabajas con datos agrupados (pacientes en centros) pero sin pesos, puedes obtener errores estándar robustos por conglomerado con sandwich y lmtest:

library(sandwich)
library(lmtest)

m_glm <- glm(erc ~ diabetes + hta + I(edad / 10) + area, data = enc, family = binomial)
coeftest(m_glm, vcov = vcovCL(m_glm, cluster = ~cluster))

Peculiaridades que conviene conocer

  • Grados de libertad: en encuestas, no son \(n-1\) sino conglomerados − estratos (aquí 60 − 2 = 58). survey lo usa en los IC de svymean con degf(dis).
  • Un solo conglomerado en un estrato (lonely PSU): la varianza no se puede calcular; se configura con options(survey.lonely.psu = "adjust") y se discute.
  • Pesos replicados (BRR, jackknife): algunas encuestas públicas los entregan en lugar de cluster/strata; se usan con svrepdesign().
  • Post-estratificación y calibración: ajustar los pesos para que reproduzcan totales conocidos del censo (edad × sexo) con postStratify() o calibrate().
degf(dis)
[1] 58
Importante🎯 En resumen
  • Una encuesta compleja tiene pesos, conglomerados y estratos; los tres entran al análisis.
  • Declara el diseño una vez con svydesign() y estima con svymean(), svytotal(), svyby() y svyglm().
  • Ignorar el diseño produce sesgo (por no ponderar) y EE subestimados (por ignorar los conglomerados).
  • Para subpoblaciones: subset(diseño, ...), nunca filtrar la base antes.
  • El efecto de diseño (deff) resume cuánto se pierde en precisión.
  • Sin survey, usa EE robustos por conglomerado (vcovCL).
