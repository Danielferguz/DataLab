Fechas y tiempos

Las fechas son una fuente constante de errores: formatos mezclados, números de serie de Excel, años con dos dígitos. El paquete lubridate (parte del tidyverse) las maneja.

library(tidyverse)
library(lubridate)
source("R/funciones_epi.R")

registro <- read_csv("Bases/registro_nefro_sucio.csv") |> rename_with(limpiar_nombres)
registro |> select(id_paciente, fecha_nac, fecha_de_ingreso) |> head(6)
# A tibble: 6 × 3
  id_paciente fecha_nac  fecha_de_ingreso
  <chr>       <chr>      <chr>           
1 P024        10/10/1970 24/08/2022      
2 P167        1948-07-13 11/08/2022      
3 P110        06/03/1948 2024-05-30      
4 P150        18/06/1982 28/03/2023      
5 P018        17/06/1987 19/12/2022      
6 P392        01/02/1973 2024-03-09

Aunque parecen fechas, son texto: en esta base unos están como dd/mm/aaaa y otros como aaaa-mm-dd.

Leer fechas: el orden importa

lubridate ofrece una función por orden de los componentes: dmy(), mdy(), ymd().

dmy("17/05/2024")          # día-mes-año
[1] "2024-05-17"
ymd("2024-05-17")          # año-mes-día
[1] "2024-05-17"
mdy("05/17/2024")          # mes-día-año (estilo estadounidense)
[1] "2024-05-17"
dmy("17-may-24")           # también acepta nombres de mes (según idioma del sistema)
[1] "2024-05-17"
Advertencia⚠️ La ambigüedad más peligrosa: 03/04/2024

¿3 de abril o 4 de marzo? R no puede saberlo: depende del formato de la fuente. Pregunta siempre cómo se registraron las fechas. Si todas las fechas con día ≤ 12 son ambiguas, revisa las que tienen día > 12 (por ejemplo, 25/03/2024 solo puede ser día-mes) para deducir el formato.

Formatos mezclados: parse_date_time()

Cuando una misma columna mezcla formatos, indica una lista de órdenes posibles; se prueban en orden:

registro <- registro |>
  mutate(
    fecha_nac        = as_date(parse_date_time(fecha_nac,        orders = c("dmy", "ymd"))),
    fecha_de_ingreso = as_date(parse_date_time(fecha_de_ingreso, orders = c("dmy", "ymd")))
  )

registro |> select(id_paciente, fecha_nac, fecha_de_ingreso) |> head(4)
# A tibble: 4 × 3
  id_paciente fecha_nac  fecha_de_ingreso
  <chr>       <date>     <date>          
1 P024        1970-10-10 2022-08-24      
2 P167        1948-07-13 2022-08-11      
3 P110        1948-03-06 2024-05-30      
4 P150        1982-06-18 2023-03-28      
sum(is.na(registro$fecha_nac))        # 0 = todas se pudieron leer
[1] 0
Tip💡 Tip práctico: verifica que no se perdieron fechas

Después de convertir, cuenta los NA nuevos. Si hay, muestra los textos originales que fallaron (filter(is.na(fecha_convertida))) para ver qué formato no previste.

Fechas de Excel guardadas como número

Excel almacena fechas como el número de días desde el 30/12/1899. Si al importar ves números como 45432:

as_date(45432, origin = "1899-12-30")
[1] "2024-05-20"

registro |>
  mutate(anio_ingreso = year(fecha_de_ingreso),
         mes_ingreso  = month(fecha_de_ingreso, label = TRUE, abbr = TRUE),
         trimestre    = quarter(fecha_de_ingreso)) |>

# A tibble: 3 × 2

         <dbl> <int>
1         2022   190

Edad desde las fechas (y comparar con la registrada)

La edad registrada puede contener errores; la calculada desde las fechas es más confiable.

registro <- registro |>
  mutate(edad_calc = as.integer(floor(time_length(interval(fecha_nac, fecha_de_ingreso), "years"))),
         dif_edad  = edad - edad_calc)

count(registro, dif_edad)               # 0 = coincide
# A tibble: 3 × 2
  dif_edad     n
     <dbl> <int>
1       -1     1
2        0   429
3      100     4
registro |> filter(dif_edad != 0) |> select(id_paciente, edad, edad_calc, fecha_nac, fecha_de_ingreso)
# A tibble: 5 × 5
  id_paciente  edad edad_calc fecha_nac  fecha_de_ingreso
  <chr>       <dbl>     <int> <date>     <date>          
1 P118          143        43 1979-12-12 2023-01-15      
2 P355          169        69 1954-05-18 2023-08-24      
3 P240          176        76 1947-05-27 2024-05-01      
4 P355          169        69 1954-05-18 2023-08-24      
5 P415           41        42 1980-03-22 2022-03-22

Cinco filas difieren: cuatro con 100 años de más (error de digitación: tres pacientes, uno de ellos con la fila duplicada; los duplicados los resolvemos en 5.5) y una con un año de diferencia, que es solo redondeo del cálculo original. Se corrige usando la edad calculada desde las fechas.

Tiempos de seguimiento

fecha_corte <- ymd("2024-06-30")

registro |>
  mutate(meses_seguimiento = time_length(interval(fecha_de_ingreso, fecha_corte), "months")) |>
  summarise(mediana = median(meses_seguimiento),
            q1 = quantile(meses_seguimiento, .25), q3 = quantile(meses_seguimiento, .75)) |>
  mutate(across(everything(), ~ round(., 1)))
# A tibble: 1 × 3
  mediana    q1    q3
    <dbl> <dbl> <dbl>
1    16.6   8.1  22.6
Advertencia⚠️ Restar fechas con - vs. time_length()

fecha2 - fecha1 devuelve días. Para años o meses reales usa time_length(interval(f1, f2), "years"): divide por 365.25 solo si no necesitas exactitud; con interval() se respeta el calendario.

Comprobaciones de coherencia temporal

Una fecha puede estar bien escrita y ser imposible:

registro |>
  summarise(
    ingreso_antes_nacimiento = sum(fecha_de_ingreso < fecha_nac),
    nacimiento_futuro        = sum(fecha_nac > today()),
    ingreso_fuera_de_rango   = sum(fecha_de_ingreso < ymd("2022-01-01") | fecha_de_ingreso > ymd("2024-12-31"))
  )
# A tibble: 1 × 3
  ingreso_antes_nacimiento nacimiento_futuro ingreso_fuera_de_rango
                     <int>             <int>                  <int>
1                        0                 0                      0
Importante🎯 En resumen
  • Las fechas llegan como texto: conviértelas con dmy(), ymd() o parse_date_time(orders = c(...)).
  • Pregunta el formato de origen: 03/04 es ambiguo.
  • Tras convertir, cuenta los NA que aparecieron.
  • Calcula edades y tiempos con time_length(interval(...), "years"); compara con lo registrado.
  • Revisa la coherencia: ingreso antes del nacimiento, fechas futuras, fuera del periodo del estudio.
