El análisis causal completo, paso a paso

Hasta aquí vimos las piezas por separado: resultados potenciales (Capítulo 3.2) y DAG y métodos de ajuste (Capítulo 3.3). Ahora las juntamos en un flujo de trabajo reproducible que puedes copiar para tus propios análisis. Seguiremos seis pasos:

Importante🎯 El flujo en seis pasos
Paso Pregunta Herramienta
1. Especificar la pregunta causal ¿Efecto de qué, contra qué, en quién, medido cómo? Ensayo objetivo (target trial), PICO
2. Dibujar las suposiciones ¿Qué causa qué? ¿Qué debo ajustar? DAG
3. Modelar las suposiciones ¿Cómo ajusto? Puntaje de propensión, pesos
4. Diagnosticar el modelo ¿Quedaron comparables los grupos? ¿Hay pesos extremos? SMD, solapamiento, pesos
5. Estimar el efecto ¿Cuál es el efecto y con qué incertidumbre? Modelo ponderado + bootstrap
6. Evaluar la sensibilidad ¿Y si faltó un confusor? E-value, análisis de sesgo cuantitativo

Paso 1. Especificar una pregunta causal

Pregunta inicial: ¿Los iSGLT2 enlentecen la progresión de la enfermedad renal?

Es demasiado vaga. Un ensayo clínico para responderla tendría que decir quiénes, qué, contra qué, y cómo se mide el resultado. Especificamos el ensayo objetivo:

Elemento Especificación
Población Adultos con ERC G3-G4 (TFGe 20-59) y diabetes tipo 2, atendidos en nefrología, sin diálisis ni trasplante
Intervención Iniciar un iSGLT2 (dosis habitual) en el momento cero
Comparador No iniciar iSGLT2 (atención habitual)
Outcome primario Pendiente anual de TFGe (mL/min/1.73 m²/año)
Outcome secundario Evento renal compuesto a 36 meses (TFGe −40 %, diálisis o trasplante)
Momento cero Visita en que se cumple la elegibilidad y se decide iniciar o no
Contraste causal Efecto de iniciar vs. no iniciar (análogo al ITT)
Estimando ATE en la población de la consulta
Nota🩺 Por qué importa especificar

“iSGLT2” puede significar tres cosas: haber recibido alguna receta, estar tomándolo de forma continua, o haberlo tomado durante todo el seguimiento. Son preguntas distintas con respuestas distintas. Escribirlo evita comparar sin saber qué se compara.

Los ensayos aleatorizados (DAPA-CKD, EMPA-KIDNEY, CREDENCE) ya han mostrado beneficio renal con esta clase de fármacos. Aquí, el objetivo es didáctico: queremos ver si, con datos de una consulta real (simulada) donde nadie fue aleatorizado, podemos acercarnos al efecto verdadero.

Paso 2. Dibujar nuestras suposiciones

Usamos el DAG del Capítulo 3.3. Lo importante para el análisis:

  • La exposición (iniciar iSGLT2) depende de edad, TFGe, albuminuria, HbA1c, ECV previa y fragilidad (no medida).
  • El desenlace depende de esas mismas variables y de la PAS.
  • Conjunto de ajuste con lo medido: edad, sexo, HbA1c, PAS, TFGe basal, albuminuria y ECV previa (según el DAG, la PAS y el sexo no son estrictamente necesarios; los incluimos porque predicen el desenlace o la ECV y suelen mejorar la precisión sin introducir sesgo).
  • La fragilidad no se mide: sabemos que dejará un sesgo residual (paso 6).

Paso 3. Modelar las suposiciones

Estimaremos el puntaje de propensión (probabilidad de iniciar iSGLT2 dado el perfil del paciente) con regresión logística y calcularemos los pesos de probabilidad inversa para el ATE.

f_ps <- isglt2 ~ edad + sexo + hba1c + pas + tfg_basal + log(uacr) + ecv

modelo_ps <- glm(f_ps, data = ckd, family = binomial())

ckd <- ckd |>
  mutate(
    ps    = fitted(modelo_ps),
    w_ate = isglt2 / ps + (1 - isglt2) / (1 - ps)
  )

ckd |> select(id, isglt2, ps, w_ate) |> head()

Paso 4. Diagnosticar el modelo

El objetivo del ajuste no es predecir bien el tratamiento: es lograr comparabilidad. Tres revisiones:

4a. Solapamiento (positividad)

Debe haber pacientes tratados y no tratados en todo el rango del puntaje de propensión.

ckd |>
  mutate(grupo = if_else(isglt2 == 1, "Con iSGLT2", "Sin iSGLT2")) |>
  ggplot(aes(ps, fill = grupo)) +
  geom_density(alpha = 0.5, color = NA) +
  scale_fill_manual(values = c("#0072B2", "#D55E00")) +
  labs(x = "Puntaje de propensión", y = "Densidad", fill = NULL)

Paso 5. Estimar el efecto causal

Con los pesos, ajustamos un modelo del desenlace. El coeficiente de isglt2 es el ATE:

modelo_ipw <- lm(pendiente_tfg ~ isglt2, data = ckd, weights = w_ate)
coef(summary(modelo_ipw))["isglt2", ]
     Estimate    Std. Error       t value      Pr(>|t|) 
 1.341753e+00  4.164872e-02  3.221596e+01 4.546084e-207

El error estándar que muestra lm() no es válido: ignora que los pesos se estimaron con otro modelo. Corregimos con bootstrap: remuestreamos pacientes y repetimos todo el proceso (modelo de PS, pesos y modelo del desenlace) en cada muestra.

# Función que ejecuta TODO el análisis en un conjunto de datos
analizar <- function(d) {
  ps <- fitted(glm(f_ps, data = d, family = binomial()))
  w  <- d$isglt2 / ps + (1 - d$isglt2) / (1 - ps)

  # Desenlace primario: ATE sobre la pendiente de TFGe
  efecto <- coef(lm(pendiente_tfg ~ isglt2, data = d, weights = w))[["isglt2"]]

  # Desenlace secundario: riesgo ponderado de evento renal a 36 meses
  r1 <- weighted.mean(d$evento[d$isglt2 == 1], w[d$isglt2 == 1])
  r0 <- weighted.mean(d$evento[d$isglt2 == 0], w[d$isglt2 == 0])

  c(efecto = efecto, riesgo_iSGLT2 = r1, riesgo_control = r0,
    dif_riesgo = r1 - r0, riesgo_relativo = r1 / r0)
}

set.seed(2025)
estimado <- analizar(ckd)
remuestras <- t(replicate(500, analizar(ckd[sample(nrow(ckd), replace = TRUE), ])))

resultados <- tibble(
  medida     = names(estimado),
  estimado   = estimado,
  ic_inf     = apply(remuestras, 2, quantile, probs = 0.025),
  ic_sup     = apply(remuestras, 2, quantile, probs = 0.975)
)
resultados |> mutate(across(where(is.numeric), ~ round(., 3)))

Resultado principal: iniciar iSGLT2 se asocia, tras ajustar por los confusores medidos, con una pendiente de TFGe 1.34 mL/min/1.73 m²/año mejor (IC 95 % bootstrap 1.27 a 1.42), en comparación con no iniciar.

Resultado secundario (escala de riesgo): el riesgo ajustado de evento renal a 36 meses fue 10.9% con iSGLT2 vs. 19.0% sin él: diferencia de -8.1 puntos porcentuales (IC 95 % -10.3 a -5.9) y NNT ≈ 12 a 36 meses.

Tip💡 Tip práctico: mismos pasos, otro desenlace

Para una diferencia de medias (pendiente de TFGe) usa un modelo lineal ponderado; para un evento binario compara las proporciones ponderadas (diferencia y razón de riesgos); para tiempo hasta un evento, usa un modelo de Cox ponderado o curvas de Kaplan-Meier ponderadas (capítulos de supervivencia). El flujo (PS → pesos → estimación → bootstrap) es el mismo.

Hasta aquí, un informe típico diría: “tras ajustar por confusores, el iSGLT2 mejora la pendiente de TFGe.” Pero la respuesta que acabamos de calcular es incorrecta. Veamos por qué.

Paso 6. Análisis de sensibilidad

Nuestra estimación asume que no hay confusores no medidos. Eso rara vez es cierto. El análisis de sensibilidad responde: ¿qué tan fuerte tendría que ser un confusor no medido para cambiar mi conclusión?

6a. El E-value

El E-value (VanderWeele y Ding) es la fuerza mínima de asociación que un confusor no medido tendría que tener, con la exposición y con el desenlace (en escala de razón de riesgos, y tras ajustar por lo medido), para explicar completamente el resultado observado.

ev <- e_value(rr = estimado[["riesgo_relativo"]], lim = resultados$ic_sup[5])
ev
# A tibble: 1 × 2
  e_value_punto e_value_ic
          <dbl>      <dbl>
1          2.89       2.37

El riesgo relativo ajustado fue 0.57. El E-value es 2.89: un confusor no medido tendría que asociarse tanto con el tratamiento como con el evento renal con un riesgo relativo de al menos 2.9 cada uno para anular el resultado, y de 2.4 para que el IC incluya 1.

Advertencia⚠️ Cómo (no) interpretar el E-value
  • Un E-value alto no demuestra que no haya sesgo: solo dice cuánta confusión haría falta para anular el efecto, no cuánta hay.
  • Compáralo con la fuerza de los confusores que sí mediste (¿la edad se asocia con riesgos relativos de 2 con el desenlace?) y con tu conocimiento clínico de lo que podría faltar (fragilidad, adherencia, acceso a la atención).

6b. Análisis de sesgo cuantitativo

Si podemos imaginar el confusor no medido (aquí, la fragilidad), podemos cuantificar su efecto. Para un confusor \(U\) estandarizado (media 0, DE 1), el sesgo de un estimador ajustado es aproximadamente:

\[ \text{sesgo} \approx \gamma \times \delta \]

donde \(\gamma\) es el efecto de \(U\) (por 1 DE) sobre el desenlace y \(\delta\) la diferencia de \(U\) (en DE) entre tratados y no tratados, ya ajustada por lo medido. Estimación corregida = estimación − sesgo.

est <- estimado[["efecto"]]

escenarios <- expand_grid(
  delta = seq(-1.5, 0, by = 0.05),     # los tratados tienen MENOS fragilidad
  gamma = seq(-1.5, 0, by = 0.05)      # la fragilidad EMPEORA la pendiente
) |>
  mutate(corregido = est - gamma * delta)

ggplot(escenarios, aes(delta, gamma, fill = corregido)) +
  geom_tile() +
  geom_contour(aes(z = corregido), breaks = 0, color = "black", linewidth = 1) +
  geom_contour(aes(z = corregido), breaks = c(0.5, 1), color = "white", linetype = "dashed") +
  scale_fill_gradient2(midpoint = 0, low = "#D55E00", mid = "white", high = "#0072B2",
                       name = "Efecto\ncorregido") +
  labs(x = "δ: diferencia de fragilidad (DE) tratados − no tratados",
       y = "γ: efecto de la fragilidad (por DE) sobre la pendiente de TFGe")

Con confusión moderada (γ = −0.5 y δ = −0.5) el efecto corregido sería 1.09; con confusión muy fuerte (γ = −1.2 y δ = −1.0) sería 0.14. El efecto estimado depende mucho de qué tan frágiles eran los pacientes que no recibieron el fármaco, algo que el registro no capta.

6c. La revelación (solo posible con datos simulados)

Como simulamos los datos, sabemos que la fragilidad existe. Usemos la versión “oráculo” para ver qué ocurre si la hubiéramos medido:

oraculo <- read_csv("Bases/ckd_isglt2_oraculo.csv", show_col_types = FALSE)
ate_verdadero <- mean(oraculo$ite)

# (1) Parámetros reales del confusor no medido (por 1 DE)
sd_frag <- sd(oraculo$fragilidad)
gamma_real <- coef(lm(pendiente_tfg ~ isglt2 + fragilidad + edad + sexo + hba1c + pas +
                        tfg_basal + log(uacr) + ecv, data = oraculo))[["fragilidad"]] * sd_frag
delta_real <- coef(lm(fragilidad ~ isglt2 + edad + sexo + hba1c + pas + tfg_basal +
                        log(uacr) + ecv, data = oraculo))[["isglt2"]] / sd_frag

# (2) IPW incluyendo la fragilidad en el modelo del PS
ps_f <- fitted(glm(isglt2 ~ edad + sexo + hba1c + pas + tfg_basal + log(uacr) + ecv + fragilidad,
                   data = oraculo, family = binomial()))
w_f  <- oraculo$isglt2 / ps_f + (1 - oraculo$isglt2) / (1 - ps_f)
ate_con_fragilidad <- coef(lm(pendiente_tfg ~ isglt2, data = oraculo, weights = w_f))[["isglt2"]]

tibble(
  análisis = c("Verdad (ATE oráculo)", "IPW sin fragilidad (lo que tendríamos)",
               "Corrección por sesgo con γ y δ reales", "IPW con fragilidad medida"),
  efecto   = c(ate_verdadero, est, est - gamma_real * delta_real, ate_con_fragilidad)
) |> mutate(efecto = round(efecto, 2))
# A tibble: 4 × 2
  análisis                               efecto
  <chr>                                   <dbl>
1 Verdad (ATE oráculo)                     0.93
2 IPW sin fragilidad (lo que tendríamos)   1.34
3 Corrección por sesgo con γ y δ reales    0.94
4 IPW con fragilidad medida                0.94
  • Los parámetros reales de la fragilidad son γ = -0.62 y δ = -0.65: cae en la zona de confusión “moderada-fuerte” del gráfico.
  • La corrección por sesgo con esos valores devuelve casi exactamente el ATE verdadero (0.93), y al medir la fragilidad el IPW lo recupera (0.94).
Importante🎯 La lección

El análisis “bien hecho” (DAG, balance excelente, bootstrap) dio un resultado precisamente estimado pero sesgado, porque faltaba un confusor. En la práctica no sabremos cuánto sesgo hay; lo que sí podemos hacer es:

  1. Pensar qué confusores faltan (con el DAG) y medirlos cuando sea posible (en este caso, una escala de fragilidad en la consulta).
  2. Cuantificar cuánto podrían cambiar los resultados (E-value, análisis de sesgo).
  3. Reportar con honestidad las limitaciones: “estimaciones ajustadas por X, Y, Z; no se midió W”.

Plantilla reutilizable

Para tu propio análisis, cambia el nombre de las variables y reutiliza esta estructura:

# 1. Datos y pregunta -------------------------------------------------------
datos <- read_csv("mis_datos.csv")           # una fila por paciente

# 2. Modelo del puntaje de propensión (confusores del DAG) -----------------
f_ps <- tratamiento ~ edad + sexo + tfg_basal + log(uacr) + hba1c   # <- tus confusores

# 3. Función que corre TODO el análisis -------------------------------------
analizar <- function(d) {
  ps <- fitted(glm(f_ps, data = d, family = binomial()))
  w  <- d$tratamiento / ps + (1 - d$tratamiento) / (1 - ps)       # ATE
  coef(lm(desenlace ~ tratamiento, data = d, weights = w))[["tratamiento"]]
}

# 4. Estimación e IC por bootstrap ------------------------------------------
set.seed(1)
est   <- analizar(datos)
boot  <- replicate(1000, analizar(datos[sample(nrow(datos), replace = TRUE), ]))
c(estimado = est, quantile(boot, c(0.025, 0.975)))

# 5. Diagnóstico y sensibilidad: balance (smd), pesos, E-value ---------------

Preguntas para reflexionar

  1. ¿Es creíble el DAG? ¿Qué flechas añadirías o quitarías?
  2. ¿Qué otro confusor podría faltar en una consulta real (adherencia, nutrición, acceso a la atención, otras terapias)?
