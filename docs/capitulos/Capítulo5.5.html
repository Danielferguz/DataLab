Control de calidad: duplicados, faltantes disfrazados y valores imposibles

Nota🩺 Escenario

La base ya tiene buenos nombres, categorías unificadas y fechas reales, y aun así sigue mal: el archivo trae 434 filas pero el servicio atiende a menos pacientes, hay presiones de 999 y de 1400 mmHg, y alguien de 176 años. Una base bien formateada todavía puede estar equivocada. Este subcapítulo reúne las revisiones que deberías hacer siempre antes de analizar.

Lo que vamos a hacer

  • Resolver duplicados con una regla escrita.
  • Convertir los faltantes disfrazados (999, -1) en NA.
  • Detectar valores imposibles con reglas clínicas y decidir según la causa.
  • Llevar un diario de limpieza y un diccionario de datos.

Los 4 pacientes con dos filas distintas pueden ser dos cosas: la segunda fila es una actualización (fecha de registro posterior) o el ID está mal digitado (dos personas distintas con el mismo ID). Se distingue mirando lo que no debería cambiar (sexo, fecha de nacimiento):

conflictos |>
  group_by(id_paciente) |>
  summarise(n = n(),
            mismo_nacimiento = n_distinct(fecha_nac) == 1,
            mismo_sexo = n_distinct(sexo) == 1, .groups = "drop") |>
  count(mismo_nacimiento, mismo_sexo)
# A tibble: 1 × 3
  mismo_nacimiento mismo_sexo     n
  <lgl>            <lgl>      <int>
1 TRUE             TRUE           4
  • mismo_nacimiento = TRUE: el mismo paciente con datos actualizados → regla “conservar el más reciente”.
  • mismo_nacimiento = FALSE: dos personas con el mismo ID → no se pueden fusionar; hay que volver a la fuente.

Aquí los 4 casos son actualizaciones, así que aplicamos la regla:

registro <- registro |>
  group_by(id_paciente) |>
  slice_max(fecha_registro, n = 1, with_ties = FALSE) |>     # regla: el registro más reciente
  ungroup()

diario <- registrar_paso(diario, "Un registro por paciente (el más reciente)", registro)
Advertencia⚠️ Cuidado: ¿qué ID está mal?

Con la regla “el más reciente” se descarta un registro sin saber si era el correcto. En un estudio real, los ID discordantes se devuelven al equipo de captura para corregirlos. Guarda un archivo con los registros descartados.

Paso 2: faltantes disfrazados

Los faltantes rara vez llegan como NA. Códigos habituales: 999, -1, 9999, "ND", "-", "". Si los dejas, contaminan los promedios. Búscalos con un resumen:

registro |> count(pas) |> filter(pas > 300) |> arrange(desc(pas))     # PAS = 999 (y otro código raro: 1400)
# A tibble: 2 × 2
    pas     n
  <dbl> <int>
1  1400     3
2   999    12
registro |> count(uacr_mg_g) |> filter(uacr_mg_g < 0)                 # UACR = -1
# A tibble: 1 × 2
  uacr_mg_g     n
      <dbl> <int>
1        -1    10

Los 999 y -1 son códigos de “no medido”: se convierten en NA. (El 1400 es otra cosa: un error de digitación; lo vemos en el Paso 3.)

registro <- registro |>
  mutate(pas = na_if(pas, 999),
         uacr = na_if(uacr_mg_g, -1))

registro |> summarise(across(c(pas, pad, uacr), \(x) sum(is.na(x))))
# A tibble: 1 × 3
    pas   pad  uacr
  <int> <int> <int>
1    12     4    10

Un faltante no es un cero ni un valor “normal”: reemplazarlo por 0 o por la media no es limpieza, introduce sesgo. Primero conviértelo a NA; qué hacer después (casos completos, imputación) es el tema del Capítulo 13.

Paso 3: valores imposibles o improbables

Define reglas clínicas con rangos plausibles y cuéntalas antes de modificar nada:

reglas <- tribble(
  ~variable,  ~minimo, ~maximo,
  "edad",         18,     100,
  "peso_kg",      30,     250,
  "talla_cm",    120,     210,
  "pas",          60,     260,
  "pad",          30,     150,
  "uacr",          0,   10000
)

registro_largo <- registro |>
  select(id_paciente, edad, peso_kg, talla_cm, pas, pad, uacr) |>
  pivot_longer(-id_paciente, names_to = "variable", values_to = "valor") |>
  left_join(reglas, by = "variable")                 # a cada valor, los límites de su variable

registro_largo |>
  filter(!is.na(valor), valor < minimo | valor > maximo) |>
  count(variable, name = "fuera_de_rango")
# A tibble: 3 × 2
  variable fuera_de_rango
  <chr>             <int>
1 edad                  3
2 pas                   3
3 peso_kg               3

Importante🎯 Regla de oro: no corrijas “a ojo”

No cambies 1400 por 140 “porque seguramente era un error de tipeo”: inventarías un dato. Si la fuente puede confirmarlo, corrígelo allí; si no, es un faltante. Cada corrección debe estar en el código, con su motivo.

Paso 4: coherencia entre variables

Algunas combinaciones son imposibles aunque cada valor, por separado, sea razonable. Escribe cada regla como una condición y cuenta los casos:

registro |>
  summarise(
    pad_mayor_o_igual_que_pas = sum(pad >= pas, na.rm = TRUE),                # presión de pulso <= 0
    sin_diabetes_pero_erc_diabetica = sum(dm == "No" & diagnostico == "ERC diabética"),
    pas_y_pad_faltantes = sum(is.na(pas) & is.na(pad))
  )
# A tibble: 1 × 3
  pad_mayor_o_igual_que_pas sin_diabetes_pero_erc_diabetica pas_y_pad_faltantes
                      <int>                           <int>               <int>
1                         2                               0                   0

Dos pacientes tienen la PAD igual o mayor que la PAS; no se corrigen (podría ser real o un error de orden), se marcan para revisión en la fuente. Las otras dos reglas dan 0: no hay incoherencias de ese tipo.

Paso 6: un reporte de calidad reutilizable

Una función pequeña resume tipos y faltantes de cualquier base:

reporte_calidad <- function(datos) {
  tibble(variable = names(datos),
         tipo = map_chr(datos, \(x) class(x)[1]),
         n_faltantes = map_int(datos, \(x) sum(is.na(x))),
         pct_faltantes = round(100 * n_faltantes / nrow(datos), 1),
         n_distintos = map_int(datos, n_distinct))
}

Importante🎯 En resumen
  1. Duplicados: elimina filas idénticas; con el mismo ID y datos distintos, usa una regla explícita (y distingue “actualización” de “ID mal digitado”).
  2. Faltantes disfrazados (999, -1, ND): conviértelos a NA; no los rellenes con ceros ni medias.
  3. Valores imposibles: define rangos clínicos, cuéntalos y decide según la causa; no inventes datos.
  4. Coherencia entre variables (PAD < PAS, diabetes y diagnóstico).
