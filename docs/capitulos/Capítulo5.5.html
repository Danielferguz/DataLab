Control de calidad: faltantes, imposibles y duplicados

Una base bien formateada todavía puede estar equivocada. Este subcapítulo reúne las cuatro revisiones que deberías hacer siempre.

library(tidyverse)
source("R/funciones_epi.R")
source("R/limpiar_registro.R")

registro <- read_csv("Bases/registro_nefro_sucio.csv") |> limpiar_basico()
nrow(registro); n_distinct(registro$id_paciente)
[1] 434
[1] 420

La base tiene 434 filas pero solo 420 pacientes distintos: hay duplicados.

1. Duplicados

Hay dos tipos y se tratan distinto:

Tipo Qué es Qué hacer
Fila idéntica La misma fila repetida (error de exportación) Eliminar las copias
Mismo ID con datos distintos Dos registros del mismo paciente que no coinciden Decidir con una regla explícita (más reciente, más completo) y documentarla 
# 1a. Filas completamente idénticas
sum(duplicated(registro))
[1] 10
registro <- distinct(registro)

# 1b. Mismo ID, filas distintas
conflictos <- registro |> group_by(id_paciente) |> filter(n() > 1) |> ungroup() |> arrange(id_paciente)
n_distinct(conflictos$id_paciente)
[1] 4
conflictos |> select(id_paciente, sexo, fecha_nac, creatinina, pas, fecha_registro) |> head(8)

En esta base, cuando un ID aparece dos veces, las filas pueden diferir porque la segunda es una actualización (fecha de registro posterior) o porque el ID está mal digitado (dos pacientes distintos con el mismo ID). Distinguirlos requiere mirar los datos que no deberían cambiar (sexo, fecha de nacimiento):

conflictos |>
  group_by(id_paciente) |>
  summarise(n = n(),
            mismo_nacimiento = n_distinct(fecha_nac) == 1,
            mismo_sexo = n_distinct(sexo) == 1, .groups = "drop") |>
  count(mismo_nacimiento, mismo_sexo)
# A tibble: 1 × 3
  mismo_nacimiento mismo_sexo     n
  <lgl>            <lgl>      <int>
1 TRUE             TRUE           4
  • mismo_nacimiento = TRUE: el mismo paciente con datos actualizados → aplicar la regla “conservar el más reciente”.
  • mismo_nacimiento = FALSE: dos personas con el mismo ID → no se pueden fusionar; hay que volver a la fuente para corregir el ID.
registro <- registro |>
  group_by(id_paciente) |>
  slice_max(fecha_registro, n = 1, with_ties = FALSE) |>     # regla: el registro más reciente
  ungroup()

nrow(registro)
[1] 420
Advertencia⚠️ Cuidado: ¿qué ID está mal?

Con la regla “el más reciente” se descarta un registro sin saber si era correcto. En un estudio real, los ID discordantes se devuelven al equipo de captura para su corrección. Guarda un archivo con los registros descartados.

2. Faltantes disfrazados

Los faltantes rara vez llegan como NA. Códigos habituales: 999, -1, 9999, "ND", "-", "". Si los dejas, contaminan los promedios.

registro |> count(pas) |> filter(pas > 300) |> arrange(desc(pas))     # PAS = 999
# A tibble: 2 × 2
    pas     n
  <dbl> <int>
1  1400     3
2   999    12
registro |> count(uacr_mg_g) |> filter(uacr_mg_g < 0)                 # UACR = -1
# A tibble: 1 × 2
  uacr_mg_g     n
      <dbl> <int>
1        -1    10
registro <- registro |>
  mutate(pas = na_if(pas, 999),
         uacr = na_if(uacr_mg_g, -1))

registro |> summarise(across(c(pas, pad, uacr), ~ sum(is.na(.x))))
# A tibble: 1 × 3
    pas   pad  uacr
  <int> <int> <int>
1    12     4    10
Advertencia⚠️ Un faltante no es un cero ni un valor “normal”

Reemplazar faltantes por 0 o por la media no es limpieza: introduce sesgo. Primero conviértelos a NA; qué hacer con ellos (casos completos, imputación) es el tema del Capítulo 13.

3. Valores imposibles o improbables

Define reglas clínicas con rangos plausibles y cuéntalas antes de modificar nada:

reglas <- tribble(
  ~variable,  ~minimo, ~maximo,
  "edad",         18,     100,
  "peso_kg",      30,     250,
  "talla_cm",    120,     210,
  "pas",          60,     260,
  "pad",          30,     150,
  "uacr",          0,   10000
)

registro_largo <- registro |>
  mutate(uacr = uacr) |>
  select(id_paciente, edad, peso_kg, talla_cm, pas, pad, uacr) |>
  pivot_longer(-id_paciente, names_to = "variable", values_to = "valor") |>
  left_join(reglas, by = "variable")

registro_largo |>
  filter(!is.na(valor), valor < minimo | valor > maximo) |>
  count(variable, name = "fuera_de_rango")
# A tibble: 3 × 2
  variable fuera_de_rango
  <chr>             <int>
1 edad                  3
2 pas                   3
3 peso_kg               3

El resultado señala: edad (los +100), peso_kg (los 0) y pas (los 1400). Veamos cada caso y decide según la causa:

registro_largo |>
  filter(!is.na(valor), valor < minimo | valor > maximo) |>
  arrange(variable, desc(valor)) |> select(id_paciente, variable, valor, minimo, maximo)

Variable Causa probable Decisión

peso_kg = 0 Peso no medido registrado como 0 NA

registro <- registro |>
  mutate(
    edad = as.integer(floor(lubridate::time_length(
             lubridate::interval(fecha_nac, fecha_de_ingreso), "years"))),
    peso_kg = na_if(peso_kg, 0),
    pas = if_else(pas > 260, NA_real_, pas)
  )

registro |> summarise(across(c(edad, peso_kg, pas), list(min = ~ min(.x, na.rm = TRUE), max = ~ max(.x, na.rm = TRUE))))

Importante🎯 Regla de oro: no corrijas “a ojo”

No cambies 1400 por 140 “porque seguramente era un error de tipeo”: inventarías un dato. Si la fuente puede confirmarlo, corrígelo allí; si no, es un faltante. Cada corrección debe estar en el código, con su motivo.

4. Coherencia entre variables

Algunas combinaciones son imposibles aunque cada valor aislado sea razonable:

registro |>
  summarise(
    pad_mayor_que_pas = sum(pad >= pas, na.rm = TRUE),
    hombres_embarazo_ejemplo = 0   # ejemplo: reglas del tipo "sexo == 'M' y embarazo == 'Sí'"
  )
# A tibble: 1 × 2

Un reporte de calidad reutilizable

reporte_calidad <- function(datos) {
  tibble(variable = names(datos),
         tipo = map_chr(datos, ~ class(.x)[1]),
         n_faltantes = map_int(datos, ~ sum(is.na(.x))),
         pct_faltantes = round(100 * n_faltantes / nrow(datos), 1),
         n_distintos = map_int(datos, n_distinct))
}

Tip💡 Tip práctico: un diario de limpieza

Lleva un registro de cuántas filas o valores cambió cada paso (filas iniciales → tras quitar duplicados → tras exclusiones). Es la base del diagrama de flujo (STROBE/CONSORT) que pedirán los revisores.

Diccionario de datos

Importante🎯 En resumen
  1. Duplicados: elimina filas idénticas; decide con una regla explícita cuando el mismo ID tiene datos distintos (y distingue “actualización” de “ID mal digitado”).
  2. Faltantes disfrazados (999, -1, ND): conviértelos a NA; no los rellenes con ceros ni medias.
  3. Valores imposibles: define rangos clínicos, cuéntalos y decide según la causa; no inventes datos.
  4. Coherencia entre variables (PAD < PAS, fechas, sexo y diagnósticos).
  5. Deja un diario de limpieza y un diccionario de datos.

Ejercicio

  2. ¿Cuántos pacientes tienen pas y pad ambos faltantes?
  3. Escribe una regla de coherencia (por ejemplo, uacr faltante pero diagnóstico “ERC diabética”) y cuenta los casos.
