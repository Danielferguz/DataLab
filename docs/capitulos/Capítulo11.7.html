Desenlaces compuestos y win ratio

Nota🩺 Escenario

El ensayo de bicarbonato tiene pocos eventos duros, así que el protocolo define el desenlace como falla renal o muerte. El HR del compuesto sale “limítrofe”. Un lector pregunta: “¿el efecto es sobre la diálisis o sobre la mortalidad? ¿Cuenta igual morir que llegar a diálisis?”. Un compuesto gana potencia, pero mezcla eventos de distinta gravedad. El win ratio es una forma de respetar esa jerarquía.

Lo que vamos a hacer

  • Analizar un compuesto y sus componentes, y comparar con la verdad.
  • Entender el win ratio comparando a mano pocos pares, y luego con los 640 pacientes.
  • Ver qué reportar cuando hay compuestos.

Paso 1: desenlaces compuestos, ventajas y trampas

En nefrología los ensayos suelen usar compuestos (falla renal o muerte o descenso de ≥ 40 % de la TFGe) para ganar eventos y potencia.

Ventaja Trampa
Más eventos → más potencia Los componentes tienen distinta gravedad (muerte ≠ aumento de creatinina)
Captura el beneficio global El componente más frecuente domina
Evita decidir “el” desenlace Efectos en direcciones opuestas se cancelan
Reduce el problema de riesgos competitivos El HR del compuesto no dice qué componente cambió

Paso 2: tiempo hasta el primer evento, y cada componente por separado

La forma estándar: tiempo hasta el primer evento del compuesto con Cox (Cap. 9), y el HR de cada componente por separado:

hr <- function(evento, datos = eca, estrato = TRUE) {
  f <- if (estrato) Surv(tiempo_meses, evento) ~ brazo + strata(centro) else Surv(tiempo_meses, evento) ~ brazo
  m <- coxph(f, data = datos)
  c(HR = unname(exp(coef(m))), exp(confint(m)))
}
hr_estimado <- rbind(`Compuesto (falla renal o muerte)` = hr(eca$estado > 0),
                     `Falla renal` = hr(eca$estado == 1),
                     `Muerte` = hr(eca$estado == 2))
round(hr_estimado, 2)
                                   HR          
Compuesto (falla renal o muerte) 0.80 0.62 1.04
Falla renal                      0.75 0.55 1.03
Muerte                           0.92 0.59 1.43

Contra la verdad

Comparamos con un ECA simulado muy grande (60 000 pacientes) con el mismo mecanismo, que nos da el HR ITT “verdadero” de cada componente:

grande <- simular_eca_bicarbonato(n = 60000, semilla = 5)$datos |>
  mutate(brazo = factor(brazo, levels = c("Placebo", "Bicarbonato")))
hr_verdad <- rbind(hr(grande$estado > 0, grande, FALSE), hr(grande$estado == 1, grande, FALSE), hr(grande$estado == 2, grande, FALSE))

tibble(desenlace = rownames(hr_estimado), HR_ensayo = hr_estimado[, 1],
       IC_ensayo = sprintf("%.2f a %.2f", hr_estimado[, 2], hr_estimado[, 3]), HR_verdad = hr_verdad[, 1]) |>
  mutate(across(where(is.numeric), \(x) round(x, 2)))
# A tibble: 3 × 4
  desenlace                        HR_ensayo IC_ensayo   HR_verdad
  <chr>                                <dbl> <chr>           <dbl>
1 Compuesto (falla renal o muerte)      0.8  0.62 a 1.04      0.86
2 Falla renal                           0.75 0.55 a 1.03      0.79

Qué vemos. El efecto sobre el compuesto (HR 0.8) viene de la falla renal (0.75); sobre la muerte el HR es 0.92 con un IC muy amplio, y la verdad es ningún efecto sobre la mortalidad (1.01). Un lector que solo viera el compuesto no sabría que el efecto es sobre la progresión renal y no sobre la mortalidad.

Paso 3: el win ratio, jerarquizar y comparar pares

El win ratio (Pocock 2012) compara cada paciente tratado con cada paciente control (todos los pares posibles) y decide quién “gana” siguiendo una jerarquía de importancia clínica:

  1. Muerte: pierde quien muere antes (si el otro sigue observado).
  2. Si empatan, falla renal: pierde quien llega antes a diálisis.
  3. Si empatan, TFGe a 24 meses: gana quien tiene mejor cambio de función.

\[ \text{Win ratio} = \frac{\text{pares en los que gana el tratado}}{\text{pares en los que gana el control}} \]

Un win ratio > 1 favorece al tratamiento. Para entenderlo, lo hacemos a mano con 4 pacientes tratados y 4 controles (hipotéticos), o sea 16 pares:

mini <- tibble(
  brazo        = rep(c("Bicarbonato", "Placebo"), each = 4),
  paciente     = c("T1", "T2", "T3", "T4", "C1", "C2", "C3", "C4"),
  tiempo_meses = c(30, 12, 36, 20,   10, 25, 36, 30),
  estado       = c( 0,  1,  0,  2,    2,  1,  0,  0),     # 0 censura, 1 falla renal, 2 muerte
  dif24        = c(-3, NA, -1, NA,   NA, NA, -6, -2)      # cambio de TFGe (si se midió)
)

comparar_par <- function(a, b) {       # a = paciente tratado, b = paciente control
  gana_t <- function(tipo) b$estado == tipo && a$tiempo_meses >= b$tiempo_meses   # el control tiene el evento y el tratado sigue observado
  gana_c <- function(tipo) a$estado == tipo && b$tiempo_meses >= a$tiempo_meses
  for (tipo in c(2, 1)) {                                    # 1.º muerte, 2.º falla renal
    if (gana_t(tipo) && !gana_c(tipo)) return("tratado")
    if (gana_c(tipo) && !gana_t(tipo)) return("control")
  }
  if (!is.na(a$dif24) && !is.na(b$dif24) && a$dif24 != b$dif24)   # 3.º TFGe: mayor cambio gana
    return(if (a$dif24 > b$dif24) "tratado" else "control")
  "empate"
}

trat <- filter(mini, brazo == "Bicarbonato"); ctrl <- filter(mini, brazo == "Placebo")
pares <- expand_grid(i = seq_len(nrow(trat)), j = seq_len(nrow(ctrl))) |>
  mutate(tratado = trat$paciente[i], control = ctrl$paciente[j],
         gana = map2_chr(i, j, \(i, j) comparar_par(trat[i, ], ctrl[j, ])))

pares |> select(tratado, control, gana) |> pivot_wider(names_from = control, values_from = gana)

Cómo leerlo. Por ejemplo, T1 contra C1: C1 murió al mes 10 y T1 seguía vivo, así que gana el tratado. T2 contra C2: ninguno murió; los dos tuvieron falla renal, T2 al mes 12 y C2 al 25, así que gana el control (tardó más). T3 contra C3: ambos censurados al mes 36 sin eventos, se decide por la TFGe (−1 frente a −6): gana el tratado. Contando, el tratado gana 9 pares, el control 7 y 0 quedan empatados: win ratio = 9/7 = 1.29.

La función win_ratio() (en R/funciones_extra_cap9_11.R) hace lo mismo para todos los pares a la vez, con matrices. Comprobamos que da el mismo resultado en el ejemplo pequeño:

win_ratio(mini)$win_ratio
[1] 1.285714

Paso 4: el win ratio en los 640 pacientes

wr <- win_ratio(eca)
wr$por_nivel
             muerte falla_renal  tfge
gana_tratado  10236       23788 16042
gana_control   9307       17975  9875
c(pares = wr$pares, win_ratio = wr$win_ratio)
       pares    win_ratio 
1.023840e+05 1.347418e+00

Los pares que se deciden en cada nivel de la jerarquía:

  • Muerte: decide cerca del 19 % de los pares y casi empata (10236 victorias del tratado frente a 9307 del control): sin efecto claro sobre la mortalidad, como vimos.
  • Falla renal: decide el nivel más grande (41 % de los pares) y gana el tratado más a menudo (23788 frente a 17975).
  • TFGe a 24 meses: decide una parte de lo que quedaba empatado (25 % de los pares), también con ventaja del tratado (16042 frente a 9875).

El tratado “gana” 49 % de los pares y el control 36 %: win ratio ≈ 1.35. Necesitamos un IC.

IC por bootstrap 

set.seed(3)
wr_boot <- replicate(300, {
  d <- eca |> group_by(brazo) |> slice_sample(prop = 1, replace = TRUE) |> ungroup()
  win_ratio(d)$win_ratio
})
ic_wr <- quantile(wr_boot, c(0.025, 0.975))
c(win_ratio = wr$win_ratio, ic_wr) |> round(2)
win_ratio      2.5%     97.5% 
     1.35      1.13      1.65

El win ratio ≈ 1.35 (IC 1.13 a 1.65) excluye 1, mientras que el HR del compuesto (0.8; IC 0.62 a 1.04) lo incluye. No es una contradicción: el win ratio aprovecha el tercer nivel (la TFGe a 24 meses, una variable continua con mucha información), que el tiempo hasta el primer evento ignora. Pero también depende de la jerarquía elegida, que debe ser preespecificada: no puede diseñarse después de ver cuál da el mejor resultado.

Contra la verdad

Con un ECA simulado de 3 000 pacientes (para que el win ratio sea más estable; el cálculo de todos los pares con 60 000 pacientes sería inmanejable), el win ratio “verdadero” de este mecanismo:

mediano <- simular_eca_bicarbonato(n = 3000, semilla = 8)$datos |>
  mutate(brazo = factor(brazo, levels = c("Placebo", "Bicarbonato")), dif24 = tfg_24 - tfg0)
wr_grande <- win_ratio(mediano)
c(win_ratio_3000 = wr_grande$win_ratio) |> round(2)
win_ratio_3000 
          1.23

Es de 1.23 (con su propio error de muestreo), compatible con el IC del ensayo de 640. Es un resumen de todos los pares, no un riesgo relativo: un win ratio de 1.3 significa que, de los pares que se deciden, el tratado gana 1.3 veces por cada victoria del control.

Advertencia⚠️ Ventajas y límites del win ratio

Ventajas: respeta la jerarquía clínica, usa la información de todos los componentes (incluso uno continuo) y no exige riesgos proporcionales. Límites: la jerarquía es subjetiva (¿es una muerte siempre peor que una diálisis?), el resultado depende del seguimiento y es difícil de traducir a medidas absolutas (NNT). Por ser una razón de pares, no se interpreta como un RR. Se recomienda acompañarlo de los efectos sobre cada componente. Variantes: win odds, net benefit (diferencia de victorias).

Tip💡 Checklist para desenlaces compuestos
Importante🎯 En resumen
  • Un compuesto gana potencia pero mezcla eventos de distinta gravedad: reporta siempre cada componente.
  • Tiempo hasta el primer evento (Kaplan-Meier, Cox) es el análisis estándar; con riesgos competitivos usa CIF (9.5).
  • El win ratio compara todos los pares tratado-control con una jerarquía (muerte → falla renal → TFGe) y resume quién gana más a menudo.
  • Su IC se obtiene por bootstrap; es un complemento, no un sustituto del HR por componente.
