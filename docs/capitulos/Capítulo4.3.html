Cómo importar datos y revisar lo que llegó

Nota🩺 Escenario

Te llegan tres archivos para el mismo proyecto: el registro del servicio en Excel, los resultados de laboratorio en un CSV exportado desde un sistema en español, y una base de investigación en Stata. Antes de calcular nada necesitas leerlos bien… y comprobar que R los entendió como tú esperabas.

Lo que vamos a hacer

  • Elegir la función correcta para cada formato.
  • Ver qué ocurre cuando se usa la equivocada (un error silencioso con la HbA1c).
  • Hacer una revisión de cinco minutos de toda base nueva.
library(tidyverse)
library(readxl)     # Excel
library(haven)      # Stata, SPSS, SAS

Lee el mensaje que imprime read_csv(): te dice cuántas filas y columnas leyó (5000 y 12) y qué tipo asignó a cada una (chr = texto, dbl = número). Si una columna que debería ser numérica aparece como chr, algo anda mal.

Si quieres controlar tú los tipos y los códigos de “faltante”, dilo explícitamente:

read_csv("Bases/ckd_isglt2.csv",
         col_types = cols(id = col_integer(), sexo = col_factor(), uacr = col_double()),
         na = c("", "NA", "999", "-"))        # estos textos se leen como faltante

Paso 3: el CSV “latino” (; y coma decimal)

Muchos Excel en español guardan los CSV con ; como separador y , como decimal. Primero veamos qué pasa si usas la función equivocada:

# 1) read_csv() espera comas: toda la fila queda en UNA sola columna
read_csv("Bases/ejemplo_pacientes_puntoycoma.csv", show_col_types = FALSE) |> dim()
[1] 150   1
# 2) read_delim(delim = ";") separa bien... pero lee "7,5" como 75
mal <- read_delim("Bases/ejemplo_pacientes_puntoycoma.csv", delim = ";", show_col_types = FALSE)
summary(mal$hba1c)
   Min. 1st Qu.  Median    Mean 3rd Qu.    Max. 
  55.00   71.25   76.00   77.79   86.75   99.00

El segundo caso es el peligroso: no hay error ni aviso, pero la HbA1c “mediana” sería 76 %. Al ver el rango se nota que algo falla, y por eso siempre se revisa. La función correcta es read_csv2():

bien <- read_csv2("Bases/ejemplo_pacientes_puntoycoma.csv", show_col_types = FALSE)
summary(bien$hba1c)
   Min. 1st Qu.  Median    Mean 3rd Qu.    Max. 
  5.500   7.125   7.600   7.779   8.675   9.900

Ahora la HbA1c va de 5.5 a 9.9 %, como corresponde.

Tip💡 Alternativa del autor: rio

El paquete rio ofrece una sola función para casi todos los formatos: import() adivina el tipo por la extensión y export() guarda. Es cómodo, pero conviene saber qué hay debajo (no se ejecuta aquí):

library(rio)
datos <- import(here("datos", "crudos", "registro.xlsx"), which = "Sheet2")   # una hoja concreta
export(datos, here("datos", "procesados", "registro.rds"))

Excel esconde problemas que el CSV no tiene: fechas guardadas como números de serie o como texto, celdas combinadas, encabezados en varias filas, colores con significado (“rojo = fallecido”) y columnas numéricas con un texto suelto ("ND", "<0.5") que las convierte enteras en texto. Cuando puedas, pide CSV y un diccionario de datos (la hoja diccionario de arriba es un buen ejemplo). Si no queda otra, skip = 3 salta filas de título y range = "A4:J200" lee un rango.

Con esta lista de verificación sabrás si la base está lista:

  1. ¿El número de filas coincide con el número de pacientes esperado?
  2. ¿Cada columna tiene el tipo correcto (número, texto, fecha)?
  3. ¿Los mínimos y máximos son clínicamente plausibles (edad 250, PAS 0, TFGe negativa)?
  4. ¿Los faltantes están codificados como NA (y no como 999 o "-")?
  5. ¿Hay IDs duplicados?
  6. ¿Las categorías están escritas de una sola manera?

Si alguna respuesta es “no”, pasa al Capítulo 5 (limpieza). El paquete skimr resume todo esto en una sola orden: skimr::skim(ckd) (no se ejecuta aquí).

Advertencia⚠️ Privacidad de datos clínicos
  • Nunca subas a un repositorio público, a la nube ni a una herramienta de IA datos con identificadores (nombre, documento, historia clínica, fecha de nacimiento exacta).
  • Trabaja con un código de paciente y guarda la tabla de equivalencias aparte y protegida.
  • Cumple las normas de tu institución y del comité de ética.
Importante🎯 En resumen
  • Cada formato tiene su función; CSV es el más seguro.
  • read_csv2() para CSV con ; y coma decimal; la función equivocada puede fallar sin avisar.
  • Con haven, usa as_factor() para convertir etiquetas en factores.
  • Revisa siempre: dimensiones, tipos, rangos, faltantes y duplicados.
  • Protege los datos identificables.
