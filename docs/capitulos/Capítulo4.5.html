Errores, avisos y cómo pedir ayuda

Nota🩺 Escenario

Son las 11 de la noche, tienes que entregar la tabla mañana y el script que funcionaba ayer devuelve en rojo: “Error: object ‘tfg_basa’ not found”. La diferencia entre un principiante y alguien con experiencia no es que el segundo no se equivoque: es que sabe leer el mensaje y qué hacer a continuación.

Este subcapítulo es tu botiquín: los errores más comunes, qué significan, cómo se arreglan y cómo pedir ayuda sin exponer datos de pacientes.

Lo que vamos a hacer

  • Distinguir error, aviso y mensaje.
  • Provocar a propósito los errores más frecuentes y leer sus mensajes.
  • Aprender una rutina de cuatro pasos para depurar.
  • Escribir una buena pregunta (un ejemplo mínimo reproducible).
# Mostramos los mensajes en inglés: así es como los encontrarás al buscarlos en internet
Sys.setenv(LANGUAGE = "en")

library(tidyverse)
ckd <- read_csv("Bases/ckd_isglt2.csv", show_col_types = FALSE)

# Función auxiliar: ejecuta código que falla y muestra el mensaje sin detener el documento
ver_error <- function(codigo) {
  limpiar <- \(m) m |> str_split_i("\n", 1) |> str_remove(" in current working directory.*")
  r <- tryCatch({ eval(parse(text = codigo)); "(se ejecutó sin error)" },
                error   = \(e) paste("ERROR:", limpiar(conditionMessage(e))),
                warning = \(w) paste("AVISO:", limpiar(conditionMessage(w))))
  cat(codigo, "\n  ->", r, "\n\n")
}

Paso 1: error, aviso y mensaje no son lo mismo

Tipo Qué significa ¿Qué hago?
Error (Error in…) R no pudo ejecutar la orden Corregirlo: no se calculó nada
Aviso (Warning) R calculó, pero algo es sospechoso Entender por qué; puede invalidar el resultado
Mensaje (Message) Información (p. ej., qué columnas leyó) Leerlo; normalmente no requiere acción
Tip💡 Si tu R habla español

R muestra los mensajes en el idioma de tu sistema. Para buscar la solución en foros suele convenir verlos en inglés: ejecuta Sys.setenv(LANGUAGE = "en") al inicio de la sesión. Entre paréntesis damos la versión en español de los más comunes.

Paso 2: los errores más frecuentes, en tres familias

Familia A: “R no encuentra lo que le pides”

# 1. Objeto no encontrado: error de tipeo, o no ejecutaste la línea que lo crea
ver_error("mean(tfg_basa)")
mean(tfg_basa) 
  -> ERROR: object 'tfg_basa' not found 
# 2. Función no encontrada: falta cargar el paquete o hay un error de tipeo
ver_error("read_dta('x.dta')")
read_dta('x.dta') 
  -> ERROR: could not find function "read_dta" 
# 3. Columna que no existe (o mal escrita)
ver_error("ckd |> select(creatinina)")
ckd |> select(creatinina) 
  -> ERROR: Can't subset columns that don't exist. 
# 4. Archivo no encontrado: ruta incorrecta o carpeta de trabajo equivocada
ver_error("read_csv('datos/no_existe.csv')")
read_csv('datos/no_existe.csv') 
  -> ERROR: 'datos/no_existe.csv' does not exist
  • 1: object not found (en español: “objeto no encontrado”). Revisa la ortografía, las mayúsculas, y si ejecutaste la línea que crea el objeto. Mira el panel Entorno.
  • 2: could not find function (“no se pudo encontrar la función”). Falta library(haven) o el paquete no está instalado.
  • 3: columns that don’t exist. Mira los nombres reales con names(ckd).
  • 4: does not exist in current working directory. Comprueba dónde estás trabajando (getwd()), usa un proyecto (4.1) y list.files() para ver qué hay en la carpeta.

Familia B: “R no entiende lo que escribiste”

# 5. Operación aritmética con texto
ver_error("'1,8' + 1")
'1,8' + 1 
  -> ERROR: non-numeric argument to binary operator 
# 6. Paréntesis sin cerrar
ver_error("mean(c(1, 2, 3")
mean(c(1, 2, 3 
  -> ERROR: <text>:2:0: unexpected end of input 
# 7. = (asigna) en lugar de == (compara) dentro de un filtro
ver_error("ckd |> filter(isglt2 = 1)")
ckd |> filter(isglt2 = 1) 
  -> ERROR: We detected a named input.
  • 5: non-numeric argument to binary operator (“argumento no-numérico para operador binario”). Un número guardado como texto (con coma decimal, por ejemplo). Revisa class() y convierte.
  • 6: unexpected end of input (“fin de entrada inesperado”). Falta cerrar un paréntesis, una comilla o una llave. RStudio resalta los pares: úsalo.
  • 7: We detected a named input. Dentro de filter() se compara con ==: filter(isglt2 == 1).

Familia C: “R funcionó, pero te engaña”

Estos son los más peligrosos: el resultado parece normal.

# 8. Aviso: convertir texto a número cuando hay valores no numéricos
ver_error("as.numeric(c('1.2', '<0.5', '3'))")
as.numeric(c('1.2', '<0.5', '3')) 
  -> AVISO: NAs introduced by coercion 
# 9. Aviso: operar vectores de longitudes distintas
ver_error("c(1, 2, 3) + c(1, 2)")
c(1, 2, 3) + c(1, 2) 
  -> AVISO: longer object length is not a multiple of shorter object length 
# 10. Sin error ni aviso: un faltante contamina el promedio
mean(c(1.2, NA, 3.4))
[1] NA
  • 8: NAs introduced by coercion (“NAs introducidos por coerción”). El "<0.5" no es un número y pasó a NA. Averigua qué valores fallaron antes de seguir.
  • 9: longer object length is not a multiple of shorter object length. R “recicló” el vector corto: casi siempre es un error de lógica.
  • 10: el resultado NA no es un error: es R diciendo que no sabe qué hacer con el faltante. Decide si ignorarlo (na.rm = TRUE) o investigarlo.

Paso 3: rutina de cuatro pasos para depurar

  1. Lee la última línea del mensaje: suele decir qué pasó.
  2. Mira en qué línea y función ocurrió (RStudio marca la línea en rojo).
  3. Pregúntate: ¿el objeto existe?, ¿está bien escrito?, ¿es del tipo que esperaba?
  4. Ejecuta el código paso a paso (una línea a la vez con Ctrl/Cmd + Enter) hasta ver dónde falla.

Paso 4: cómo pedir ayuda (a una persona o a una IA)

Una buena pregunta incluye un ejemplo mínimo reproducible: el menor código que muestra el problema, con datos que se pueden compartir. Muchas veces, al armarlo, encuentras tú mismo la solución.

# Plantilla: ejemplo mínimo reproducible
library(tidyverse)

datos <- tibble(                      # datos FICTICIOS, no reales
  tfg  = c(95, 62, NA, 33),
  sexo = c("M", "F", "F", "M")
)

datos |> summarise(media = mean(tfg))   # Devuelve NA; ¿cómo ignoro el faltante?

sessionInfo()   # versión de R y de los paquetes: úsalo al pedir ayuda

Al pedir ayuda incluye siempre: qué querías hacer, el código, el mensaje de error completo y sessionInfo(). El paquete reprex automatiza el formato (reprex::reprex() copia código y salida listos para pegar en un foro).

Advertencia⚠️ Privacidad y confianza al pedir ayuda
  • No pegues datos reales de pacientes (ni siquiera “solo unas filas”) en foros ni en asistentes de IA. Crea datos ficticios con tibble() que reproduzcan el problema.
  • Las respuestas de una IA pueden sonar seguras y estar equivocadas: verifica con un ejemplo pequeño, cuyo resultado conoces, antes de usar el código en tu análisis real.

Paso 5: dónde buscar ayuda

  • ?función en RStudio: documentación oficial y ejemplos.
  • Viñetas del paquete (vignette("nombre")): guías con ejemplos.
  • R for Data Science (r4ds.hadley.nz): para aprender tidyverse.
  • Stack Overflow y Posit Community: preguntas ya respondidas.
  • Tu grupo de estudio: la ayuda más rápida suele ser un colega.
Importante🎯 En resumen
  • Error = no se ejecutó; aviso = ejecutó pero sospecha; mensaje = información.
  • Los errores se agrupan en tres familias: no encuentra algo, no entiende lo escrito y funciona pero engaña (esta última es la más peligrosa).
  • Lee la última línea del error, revisa nombres, tipos y rutas, y ejecuta paso a paso.
  • Pide ayuda con un ejemplo mínimo reproducible con datos ficticios.
  • Nunca compartas datos reales de pacientes.
